여덟 단계

서버를 먼저 세우고 프론트를 나중에 만든다. 그래야 새 프론트가 처음부터 새 API 만 본다.

단계끝났다고 보는 기준
0목표 확정이 그림과 ROADMAP.md
1릴리스 규칙버전이 한 곳에서 생성된다. 여섯 곳 수동 동기화가 사라진다
2v3 걷어내기frontend/ 15,090줄이 지워지고 굽는 일이 backend/ 로 간다
3Neon 스키마마이그레이션이 빈 DB 에서 끝까지 돈다. ERD 를 다시 굽는다
4인증·권한 서버테스트를 먼저 쓴다. 규칙 검사 11개가 지키던 것이 서버 테스트로 옮겨진다
5도메인 API즐겨찾기·내 포켓몬·트레이너 코드·승인이 REST 로 돈다. 계정 삭제가 트랜잭션 하나
6Next.js 앱/mon/25 가 완성된 HTML 로 온다. 옛 해시 주소가 전부 이어진다
7배포 이관Vercel + Cloud Run + Neon 으로 운영이 선다. Firebase 가 사라진다
8수집과 지표COLLECT_URL 을 켠다. 색인된 페이지 수와 검색 유입을 본다
