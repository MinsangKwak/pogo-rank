# 광고 준비와 운영 절차

[프로젝트 소개](../README.md) · [운영 가이드](OPERATIONS.md) · [인프라](INFRA.md#pages)

**광고 코드는 준비됐지만 실제 송출은 꺼져 있습니다.** 2026-10-15 기록 기준으로 운영 호스팅 이전, ads.txt 소유권 확인과 AdSense 검토 요청을 마쳤습니다. `ADS_FROM`은 아직 설정되지 않았습니다.

이 문서는 구현된 노출 조건과 활성화 절차를 설명합니다. 광고 승인 상태·단위 설정·동의 메시지는 각 서비스의 콘솔에서 확인합니다.

## 현재 상태

| 구분 | 상태 |
| --- | --- |
| 운영 웹 | Cloudflare Pages. v5.10.2 배포 성공 확인 |
| 광고 코드 | dev·main·deploy 반영. 실제 송출은 비활성 |

## 언제 광고를 표시하나요?

로그인 확인이 끝난 익명 사용자 중 통계를 거부하지 않은 경우에만 광고 영역을 구성합니다. 로그인 상태 확인 중, 승인 대기·승인 계정, 재확인 실패 상태에서는 표시하지 않습니다.

약관·개인정보처리방침·설정·로그인이 필요한 화면과 잠금 화면도 제외합니다. 판정은 `adsVisible`, `adFreeRoute`에 모아 두었습니다.

| 화면 조건 | 영역 |
| --- | --- |
| 너비 1280px 이상, 높이 760px 이상 | 좌우 160×600과 하단 영역 |
| 위 조건에 해당하지 않는 화면 | 하단 영역 |
| 모바일(999px 이하) | 문서 하단의 320×50 영역 |

실제 광고 모드에서는 영역을 화면에 고정하지 않습니다. 로그인·동의 상태가 바뀌면 표시 여부를 다시 판단합니다. dev에서 자리만 확인할 때는 `?adPreview=1`을 사용합니다.

## 활성화 절차

운영 결정은 승인 당일을 시행일로 설정하는 것입니다. 이전의 7일 전 고지 계획은 2026-10-15에 변경됐으며, 실제 시행일과 안내 문구를 함께 확인합니다.

1. **콘솔 확인:** AdSense 승인 상태와 동의 메시지 설정을 확인합니다.
2. **광고 단위 준비:** 좌우 160×600, 하단 320×50 디스플레이 단위를 만들고 ID를 기록합니다.
3. **설정 반영:** `NEXT_PUBLIC_ADS=live`, 단위 ID 3개, `ADS_FROM`을 설정합니다. 미국 요청의 RDP 표시는 적용할 속성과 실제 요청을 확인합니다.
4. **문구·검사 확인:** 같은 시행일의 한·영 패치노트, 약관·방침, 재동의 조건과 `adslegal.test.ts`를 확인합니다.
5. **범위 검토 후 반영:** 광고 활성화에 필요한 변경만 dev → main → deploy에 반영합니다.
6. **실제 동작 확인:** 로그인 전후, 통계 거부, 제외 화면, 반응형 배치와 광고 요청을 확인합니다.

시행일은 한국 시간 0시를 기준으로 합니다. 날짜 이전에는 모드가 설정돼 있어도 광고를 요청하지 않습니다. `live`는 운영 도메인 `moncamp.kr`과 필요한 식별자가 모두 준비된 경우에만 활성화됩니다.

| 파일 | 책임 |
| --- | --- |

| `web/src/components/AdSlots.tsx` | 보이는 영역의 단위 연결, 스크립트 중복 로드 방지 |
| `web/src/styles/cinema/ads.css` | 좌우·하단 배치와 반응형 크기 |
| `web/app/layout.tsx` | 첫 렌더링 전 광고 표시 상태 반영 |
| `web/app/ads.txt/route.ts` | 빌드 설정의 게시자 ID로 ads.txt 생성 |
| `Legal.tsx` · `legalMeta.ts` | 시행일에 따른 광고 조항과 문서 버전 |

비개인 광고 요청을 기본으로 하며, 자동 광고는 사용하지 않습니다. 빈 영역과 광고 차단 상태도 확인합니다. 영역 크기를 미리 확보하는 것은 레이아웃 이동을 줄이기 위한 구현이며 실제 CLS 측정 결과와는 구분합니다.

## 반영 후 확인

- 시행일이 약관·방침·패치노트에서 일치하는지 확인합니다.
- 로그인한 사용자와 통계 거부 사용자에게 광고 요청이 발생하지 않는지 확인합니다.
- 운영 도메인의 ads.txt와 AdSense 콘솔 상태를 확인합니다.
- 동의 메시지와 지역별 요청 설정을 확인합니다. 실제 광고를 직접 클릭해 시험하지 않습니다.

## 승인 당일 할 일 (Claude 가 합니다 — 주인은 '승인됐어' 와 단위 ID 셋만)

1. AdSense → 광고 → 광고 단위 기준 → 디스플레이 광고 셋(고정 크기 `왼쪽 160×600` · `오른쪽 160×600` · `바닥 320×50`)을 만들고 단위 ID(숫자)를 받는다.
2. `web/.env.production` — `NEXT_PUBLIC_ADS=live` · `NEXT_PUBLIC_ADSENSE_SLOT_LEFT/RIGHT/BOTTOM` 에 ID 셋. `web/src/lib/legalMeta.ts` — `ADS_FROM` 에 그 날짜.
3. 같은 날짜로 패치노트(한 · 영) 한 줄 — '오늘부터 로그인하지 않은 화면에 광고가 표시돼요. 로그인하면 광고 없이 이용할 수 있어요'. `adslegal.test.ts` 가 시행일 당일까지의 고지를 찾는다.
4. dev → main · deploy. 약관 · 방침의 광고 조항, '시행일에 알린다' 문장, 두 판(다시 동의), 광고 자리가 그 날 0시(한국 시간)부터 함께 켜진다.

시행일 전에는 빌드 모드가 켜져 있어도 자리가 안 선다(`lib/ads.ts` `adsModeNow` · `app/layout.tsx` 첫 렌더링 전 스크립트). dev 에서 배치를 보려면 주소 끝에 `?adPreview=1`.

> **운영 반영** — dev 의 다른 내용(새 디자인 · v5.10.x)은 여전히 main · deploy 에 올리지 않습니다(운영자 요청 2026-10-13 · 10-14). **광고 코드만 예외** — 승인 당일 바로 켜도록 광고 자리 · 판정 · 약관 조항을 운영에 먼저 올립니다(운영자 요청 2026-10-15). 시행일이 없는 동안 운영 화면은 그대로입니다.

**코드로는 못 고치는 것 (운영 판단)**

- **저작권 심사 위험** — 포켓몬 스프라이트 · 이름과 배너의 포켓몬 그림(자체 제작 일러스트)은 권리자의 저작물이다. 비슷한 팬 사이트(도감 · 순위)들이 AdSense 를 쓰고 있어 흔히 통과하지만, Google 이 '저작권 보호 자료' 로 거절할 수 있다. 거절되면 이의 신청에 비공식 · 출처 고지 · 권리자 요청 시 삭제(약관 5항)를 적는다.
- **호스팅** — Vercel Hobby 는 광고를 금지한다(INFRA §8). **2026-10-15 정정**: 앞서 이 문서와 대화에서 'dev 프로젝트가 Pro' 라고 적었으나 확인하지 않은 말이었고, 실제로는 Vercel 계정(팀)이 Hobby 였다(운영자가 대시보드에서 확인 — 플랜은 계정 단위라 운영 · dev 프로젝트가 같다). 그래서 운영을 Cloudflare Pages 로 옮긴다 — 정적 빌드 `npm run build:static` · 배포 `deploy-pages.yml` · 주소 전환 `cutover-pages.yml`(status → attach, 되돌리기 rollback). 광고는 Pages 로 넘어간 뒤에만 켠다.

## 6. 하지 않을 것

- 로그인한 사람 · 통계를 끈 사람에게 광고를 보이는 것 — `adsVisible` 한 곳에서만 판정한다.
- 자동광고(Auto ads) — 자리를 Google 이 정해 로그인 제외 · 광고 없는 화면 · 배치 규칙이 깨진다.
- 약관 개정(`ADS_FROM`) 없이 운영에 `placeholder` 나 `live` 를 켜는 것 — `adslegal.test.ts` 가 `.env.production` 의 `off` 를 지킨다.
- `public/ads.txt` 를 손으로 두는 것 — 경로가 겹친다(검사가 막는다).
